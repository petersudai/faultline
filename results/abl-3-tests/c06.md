## Summary
This PR changes the compose function signature (swapping parameter order from `onNotFound, onError` to `onError, onNotFound`) and implements error handler inheritance for sub-apps via route composition. All internal call sites are updated, but the signature change is a breaking change for external callers of compose.

## Findings (3)

### 🟡 Medium — src/compose.ts:10 — breaking-change

The compose function signature changed from `compose(middleware, onNotFound?, onError?)` to `compose(middleware, onError?, onNotFound?)`. This is a breaking change for any external code calling compose directly. While all internal call sites in hono.ts and tests are updated, external consumers of this exported function would break.

→ Check: Verify that compose is not part of the public API contract, or document this as a breaking change. Check if there are any external packages or examples that call compose directly.

### 🟡 Medium — src/hono.ts:125 — other

The identity check `app.errorHandler === errorHandler` relies on object reference equality with the module-level errorHandler function. This is fragile: if a sub-app's errorHandler is manually set to a different function object that has identical behavior, the wrapping logic will incorrectly wrap it. Additionally, this check is not symmetric—there's no equivalent check for notFoundHandler, which is inconsistent.

→ Check: Consider using a flag or property to track whether a handler is the default, rather than relying on reference equality. Verify the test at line 974-978 actually exercises the sub-app's errorHandler being called (not the app's).

### 🟢 Low — src/hono.test.ts:1028 — test-gap

The test at line 1028-1032 expects `/sub/implicit-404` to be handled by the app's notFound handler, not the sub's. This is correct behavior (routes are merged, so sub-app's notFound is never invoked), but there is no test verifying that a sub-app's notFound handler IS called when it should be (e.g., when a route matches the sub-app prefix but not any sub-app route). The notFound test suite only tests the app-level handler.

→ Check: Add a test case where a sub-app has a custom notFound handler and verify it is NOT called (since routes are merged), to document this design decision explicitly.
