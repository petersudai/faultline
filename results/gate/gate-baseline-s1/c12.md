## Summary
This PR fixes a bug where the `compress` middleware was buffering server-sent events (SSE) instead of streaming them by excluding `text/event-stream` content type from compression. The fix is minimal and well-tested, with a regex update to skip compression for SSE and a corresponding test case. The change is low-risk as it only affects SSE streams and doesn't alter existing behavior for other content types.

## Findings (2)

### 🟢 Low — src/utils/compress.ts — other

The regex modification is complex and uses a negative lookahead `(?!event-stream(?:[;\s]|$))` to exclude text/event-stream. While the logic appears correct, regex changes carry inherent risk of unintended side effects. The pattern should be validated against edge cases like 'text/event-stream; charset=utf-8' and 'text/event-stream-custom'.

→ Check: Verify the regex handles all valid Content-Type header formats for SSE (e.g., with charset, boundary parameters) and doesn't accidentally exclude other text/* types that should be compressible.

### 🟢 Low — src/middleware/compress/index.test.ts — test-gap

The test only verifies that SSE is not compressed (13000 bytes uncompressed). It doesn't verify that the SSE stream actually works correctly end-to-end (i.e., that messages are streamed in real-time rather than buffered).

→ Check: Consider adding a test that verifies SSE messages are received incrementally/streamed rather than all at once, to ensure the fix actually solves the original buffering problem.
