## Summary
This PR adds a `basePath` constructor option to Hono and deprecates the `app.basePath()` method. It refactors the internal `_basePath` field to a private field `#basePath`, updates the constructor signature to accept a `HonoOptions` type, and removes an overload of `route()` that accepted a single argument. The change is backward-compatible since `app.basePath()` still works but is marked deprecated.

## Findings (5)

### 🟡 Medium — src/hono-base.ts:128 — api-contract

The constructor now uses `Object.assign(this, options)` after deleting `options.strict`, but `options.basePath` is not deleted before the assign. This means if a subclass or external code relies on inspecting the constructor parameter object, the behavior changes. More critically, the `#basePath` field is set after `Object.assign`, which could cause issues if `Object.assign` tries to set a property named `basePath` (though private fields prevent this). The order of operations (assign then set private field) is correct, but the pattern is fragile.

→ Check: Verify that no subclasses or external code depend on the constructor parameter object structure or side effects. Confirm that the private field `#basePath` initialization happens correctly in all inheritance chains (Hono, quick preset, tiny preset).

### 🟡 Medium — src/hono-base.ts:156 — breaking-change

The `route()` method implementation changed from calling `this.basePath(path)` to directly cloning and setting `#basePath`. While functionally equivalent, this removes the indirection through the deprecated `basePath()` method. If any code subclasses Hono and overrides `basePath()` expecting it to be called by `route()`, that override will no longer be invoked. This is a subtle breaking change for advanced users.

→ Check: Search the codebase and common examples for any subclasses that override `basePath()` and rely on it being called by `route()`. Document this behavior change in migration notes.

### 🟢 Low — src/hono-base.ts:263 — other

The `addRoute()` method previously checked `if (this._basePath)` before merging, but now unconditionally calls `mergePath(this.#basePath, path)`. Since `#basePath` is initialized to `'/'` by default, `mergePath('/', path)` should return `path` unchanged, so behavior is preserved. However, this removes a micro-optimization that skipped merging when basePath was falsy. The change is safe but worth confirming the `mergePath` function handles the `'/'` case correctly.

→ Check: Verify that `mergePath('/', '/foo')` returns `'/foo'` and that no edge cases exist with empty or root paths.

### 🟢 Low — src/hono-base.ts:75 — test-gap

If the constructor is bypassed or if a subclass fails to call `super()`, the field will be uninitialized. The tests added cover the happy path but don't test edge cases like subclasses that don't properly initialize the parent.

→ Check: Verify that all subclasses (Hono, quick preset, tiny preset) properly call `super(options)` and that there are no code paths where `#basePath` could be accessed before initialization.
