## Summary
This PR refactors Hono's constructor to accept a `basePath` option and deprecates the `app.basePath()` method. The change includes comprehensive test coverage for the new pattern. The main risk is that `clone()` does not preserve `#basePath`, creating a subtle contract violation where cloned instances lose their basePath unless explicitly reassigned.

## Findings (2)

### 🔴 High — src/hono-base.ts:138 — unhandled-edge-case

The `clone()` method creates a new instance without preserving `#basePath`. It initializes only `router` and `getPath`, leaving `#basePath` at its default value of `'/'`. While `route()` and `basePath()` explicitly reassign `#basePath` after cloning, this is a fragile pattern. Any future code path that calls `clone()` and then uses the instance without explicitly setting `#basePath` will silently lose the original basePath. This violates the semantic contract of cloning—a clone should be a faithful copy of the original state.

→ Check: Verify that `clone()` preserves `#basePath` by either: (1) modifying the constructor call to pass `basePath: this.#basePath`, or (2) explicitly assigning `subApp.#basePath = this.#basePath` immediately after `clone()` in all call sites. Audit all current and potential future uses of `clone()` to ensure none rely on the implicit default.

### 🟡 Medium — src/hono-base.ts:128 — api-contract

The constructor now accepts `options.basePath` but does not validate or document its interaction with the deprecated `basePath()` method. If a user passes both `basePath` in the constructor and later calls `.basePath()`, the behavior is correct (the method overwrites), but this is not explicitly documented. Additionally, the `#basePath` field is initialized to an uninitialized state (no default assignment in the field declaration), then set in the constructor. This is inconsistent with the pattern used for other fields like `path`.

→ Check: Add a default initializer to the `#basePath` field declaration (e.g., `#basePath: string = '/'`) to make the initialization explicit and consistent. Consider adding a JSDoc note on the constructor explaining that `basePath` in options is the preferred way to set the base path, and that calling `.basePath()` afterward will override it.
