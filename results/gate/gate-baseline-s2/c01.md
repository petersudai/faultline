## Summary
This PR adds a fast-path optimization to `c.json()` matching the existing optimization in `c.text()`, avoiding unnecessary allocations when no status, headers, or finalized state exist. The change uses `Response.json()` for the fast path instead of manually constructing a Response with inline headers.

## Findings (4)

### 🟡 Medium — src/context.ts:712 — api-contract

The fast path uses `Response.json(object)` which has different behavior than the slow path `this.#newResponse(JSON.stringify(object), ...)`. Response.json() automatically sets Content-Type and may handle serialization differently. The PR description mentions using 'inline header object' but the code uses Response.json() which creates a Headers instance, not a plain object. This contradicts the stated optimization goal and may not achieve the claimed performance benefits in the node-server adapter.

→ Check: Verify that Response.json(object) produces identical output (including header type and serialization) as JSON.stringify(object) passed through #newResponse(). Confirm whether Response.json() creates a Headers instance or plain object, and whether this aligns with the node-server adapter's optimization expectations.

### 🟡 Medium — src/context.ts:660 — other

The new #useFastPath() helper method checks three conditions, but the fast path in json() adds two more conditions (!arg && !headers). This is inconsistent with the text() method which also checks these same two conditions. The helper is incomplete and callers must remember to add the extra checks. This could lead to bugs if other methods use #useFastPath() without the additional guards.

→ Check: Consider whether #useFastPath() should include the !arg && !headers checks, or document clearly that callers must verify these conditions separately. Review if any other methods might incorrectly use this helper without the full set of guards.

### 🟢 Low — src/context.ts:707 — test-gap

The PR adds a new code path (Response.json() fast path) but the description doesn't mention test coverage for this path. The fast path has different behavior than the slow path and should be tested to ensure it handles edge cases (circular references, undefined values, custom serializers) identically.

→ Check: Verify that tests exist covering c.json() with various object types, and that both fast and slow paths are exercised. Check for tests with circular references, undefined values, and other JSON edge cases.

### 🟢 Low — src/context.ts:681 — other

The text() method was refactored to use the new #useFastPath() helper, changing from an inline condition to a method call. While functionally equivalent, this adds a method call overhead in the hot path. For a performance-focused PR, this is a minor concern but worth noting.

→ Check: Confirm that the method call overhead of #useFastPath() is negligible compared to the optimization gains, or consider inlining the check in both methods.
