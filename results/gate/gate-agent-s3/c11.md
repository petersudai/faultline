## Summary
This PR adds support for greedy regex patterns followed by static path components (e.g., `/:dirs{.+}/file.html`) by introducing lookahead assertions and a queue-based node traversal mechanism. The core risk is an untested edge case where the same greedy pattern is used both with and without a subsequent component, creating inconsistent cache keys and node structures.

## Findings (2)

### 🟡 Medium — src/utils/url.ts:62 — api-contract

The pattern tuple's first element becomes the cacheKey (e.g., ':dirs{.+}#file.html') when lookahead is present, but remains the original label (e.g., ':dirs{.+}') otherwise. This is propagated to trie-router as the child node key (node.ts line 50). A greedy pattern registered both standalone ('/:dirs{.+}') and with a suffix ('/:dirs{.+}/file.html') would create two separate nodes with different keys, potentially causing routing conflicts or missed matches. No test covers this scenario.

→ Check: Add a test registering the same greedy pattern both standalone and with a subsequent component (e.g., router.add('GET', '/:dirs{.+}', 'standalone') and router.add('GET', '/:dirs{.+}/file.html', 'with-suffix')) and verify both routes match correctly without interference.

### 🟡 Medium — src/router/trie-router/node.ts:180 — unhandled-edge-case

The queue-based lookahead mechanism (curNodesQueue) uses the component count (number of '/' in the matched string) as the queue index. If a greedy pattern matches multiple segments (e.g., 'foo/bar/baz'), the componentCount is 2, and the node is queued for processing 2 iterations later. However, if the path has fewer remaining segments than componentCount, the queued node is never processed. For example, a pattern '/:prefix{.+}/end' matching '/a/b/end' would queue the node at index 2, but only 1 iteration remains after the match, leaving the queued node unprocessed.

→ Check: Trace through a scenario where a greedy pattern consumes multiple segments and verify that queued nodes are processed even when fewer segments remain in the path. Add a test case like '/:prefix{.+}/end' matching '/a/b/c/end' to ensure the queued continuation is reached.
