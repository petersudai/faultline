### 🟡 Medium — src/context.ts:119 — api-contract

Callers that previously relied on the return type being exactly `Response` may now see different type narrowing behavior or fail type checks if they use `instanceof Response` or similar runtime checks. The `TypedResponse` marker is a type-only construct, but its presence in the return type signature is a breaking change to the API contract.

→ Check: Search the codebase and any known consumers for code that checks `c.body(...) instanceof Response` or uses type guards that assume the return type is exactly `Response`. → Check: Consider adding a runtime assertion to the new test that actually calls the endpoint and verifies the status codes are correct, not just that the types are correct.
