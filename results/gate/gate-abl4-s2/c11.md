## Summary
This PR adds support for greedy route patterns with subsequent static components (e.g., `/:dirs{.+}/file.html`). The implementation uses lookahead assertions in regex patterns and a queue mechanism to handle multi-segment greedy matches. A critical regex bug in the trie-router will cause incorrect routing behavior for greedy patterns matching multiple path segments.

## Findings (1)

### 🔴 High — src/router/trie-router/node.ts:180 — error-handling

The regex `/\\/` matches backslashes, not forward slashes. It should be `/\//g` to count the number of path segments consumed by a greedy match. This causes `componentCount` to always be 0, breaking the queue mechanism that handles multi-segment greedy matches. For example, a pattern like `/:dirs{.+}/file.html` matching `/foo/bar/file.html` should queue the child node at index 1 (one slash in `foo/bar`), but instead queues at index 0, causing incorrect routing.
