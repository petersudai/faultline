## Summary
This PR adds a fallback mechanism for environments where `res.clone()` is not supported (e.g., AWS Lambda). However, the fallback path processes the entire response body as a single ArrayBuffer and calls the digest generator once, while the original path streams chunks and calls the generator multiple times with accumulated hashes. This architectural difference will produce different ETag values for the same response body depending on which code path is taken, breaking ETag consistency and potentially causing cache validation failures.
