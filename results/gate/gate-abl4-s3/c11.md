## Summary
This PR adds support for greedy route parameters followed by static path components (e.g., `/:dirs{.+}/file.html`). The changes modify pattern matching in three routers to use positive lookahead assertions and introduce a queue-based node processing system in the trie-router. Comprehensive tests are added for the new functionality.

## Findings (1)

### 🟡 Medium — src/router/trie-router/node.ts:203 — other

The curNodesQueue is indexed by componentCount (number of slashes in greedy match) but processed sequentially via shift(). If multiple greedy patterns match different numbers of components in the same iteration, the queue indexing may not align with sequential shifting. For example, if one pattern queues nodes at index 2 and another at index 1 in the same iteration, shift() will retrieve index 0 (undefined), then index 1, skipping the index 2 nodes. The logic assumes nodes are queued in strictly increasing order of componentCount, but this is not enforced.
