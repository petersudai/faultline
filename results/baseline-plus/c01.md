## Summary
This PR adds a fast-path optimization to `c.json()` matching the existing optimization in `c.text()`. When no status, headers, or finalized state exist, it uses `Response.json()` directly instead of going through `#newResponse()`. The change is minimal and mirrors an existing pattern, but introduces a subtle behavioral difference in the fast path.

## Findings (3)

### 🟡 Medium — src/context.ts:712 — api-contract

The fast path uses `Response.json(object)` which creates a Response with an inline header object `{ 'Content-Type': 'application/json' }`, while the slow path uses `#newResponse()` which creates a `Headers` instance. This means the fast path returns a Response with a plain object in headers, while the slow path returns one with a Headers instance. Although both are valid Response objects, code that inspects `response.headers instanceof Headers` or relies on specific header object types could behave differently. The PR description mentions this is intentional for the node-server adapter optimization, but it's a behavioral divergence between code paths.

→ Check: Verify that all code consuming `c.json()` responses (especially in adapters like @hono/node-server) correctly handles both plain object headers and Headers instances. Check if there are any tests that verify header behavior consistency between fast and slow paths.

### 🟢 Low — src/context.ts:681 — other

The `c.text()` fast path creates `new Response(text)` without explicit headers, relying on the default Content-Type behavior. However, `c.json()` fast path uses `Response.json(object)` which is a built-in method that sets Content-Type automatically. While both should work correctly, they use different Response construction methods. This inconsistency is minor but worth noting for maintainability.

→ Check: Confirm that `Response.json()` is widely supported in all target environments (browsers, Node.js versions, edge runtimes) that Hono supports. Check if there are any polyfills or fallbacks needed.

### 🟢 Low — src/context.ts:660 — test-gap

The new `#useFastPath()` helper method is extracted and used in both `text()` and `json()`, but there's no visible test coverage shown for the fast path conditions. The PR should include tests verifying that the fast path is taken when conditions are met and that the slow path is taken when any condition fails (e.g., when headers are set, status is set, or context is finalized).
