## Summary
This PR relaxes TypeScript type constraints for `createMiddleware` by automatically filling undefined `Bindings` or `Variables` with `any`, allowing nested middleware with partial type specifications to compose without type errors. The change is type-only and adds a test case demonstrating the new behavior.

## Findings (3)

### 🟡 Medium — src/helper/factory/index.ts:245 — api-contract

The `AddAnyToEnv` type transformation silently converts undefined `Bindings` or `Variables` to `any`, which weakens type safety. A middleware author specifying only `{ Variables: Variables }` will now have `Bindings: any` injected, potentially masking type mismatches at call sites. This is a behavioral change to the type contract that could hide bugs in strict codebases.

→ Check: Verify that existing code relying on strict type checking of `Bindings` or `Variables` in `createMiddleware` still catches errors as expected. Consider whether the relaxation should be documented as a breaking change in type safety.

### 🟡 Medium — src/helper/factory/index.ts:250 — other

The new `E2` type parameter is computed from `E` but the function signature uses `E2` for the middleware handler while still accepting `E` as the generic parameter. This creates a subtle indirection: callers pass `E`, but the actual handler operates on `E2`. If a caller explicitly specifies both `E` and `E2`, or if TypeScript's inference picks the wrong one, the type transformation may not apply as intended.

→ Check: Test that type inference works correctly when `createMiddleware` is called with explicit type arguments vs. inferred types. Verify the behavior in edge cases like `createMiddleware<{ Bindings: B }>` vs. `createMiddleware<{ Variables: V }>` vs. `createMiddleware<{}>` vs. `createMiddleware` with no args.

### 🟢 Low — src/helper/factory/index.test.ts:41 — test-gap

The test is a compile-time type check (no runtime assertions). It verifies that the code type-checks, but does not verify runtime behavior or that the middleware actually executes correctly with the relaxed types. If the type transformation breaks at runtime (e.g., due to incorrect `Simplify` application), the test would not catch it.

→ Check: Add a runtime test that actually invokes the middleware chain and verifies that `c.env` and `c.var` are accessible and functional, not just that the code compiles.
