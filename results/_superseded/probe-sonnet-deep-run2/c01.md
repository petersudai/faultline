## Summary
This PR adds a fast path to c.json() mirroring the existing c.text() optimization, using Response.json(object) directly when no status/headers/#res/finalized state exists. The main behavioral difference to verify is that Response.json() may throw or behave differently than JSON.stringify for values that don't serialize (e.g. circular references, BigInt), and its runtime support/behavior should be confirmed across all target environments (Node, Cloudflare Workers, Deno, Bun, etc.). This is a narrow, well-scoped perf change closely modeled on a previously accepted pattern (text fast path), so overall risk is low.

This diverges from the old code which always called JSON.stringify explicitly and passed through #newResponse.
