## Summary
The PR adds a fallback path in the etag middleware: if `res.clone()` throws (e.g. AWS Lambda), it reads the whole body via `res.arrayBuffer()` and reconstructs `res`, then computes the digest from the ArrayBuffer instead of streaming. `digest.ts` was extended to accept either a stream or an ArrayBuffer, which is backward compatible for existing callers. The main risk is that the `try/catch` around `generateDigest(res.clone().body, ...)` is too broad — it will also swallow errors thrown by a custom `generateDigest` option or other unrelated failures (not just clone-unsupported), causing the middleware to silently re-buffer the whole body and retry rather than surfacing/propagating the original error, which changes error-handling behavior and adds unbounded memory buffering for large bodies in a case that isn't actually about clone support.

## Findings (2)

### 🟡 Medium — src/middleware/etag/index.ts:95 — error-handling

The try/catch wraps both `res.clone()` and the subsequent `generateDigest` call. Any error thrown inside `generateDigest` (e.g. from a user-supplied `options.generateDigest` function, not just an unsupported clone()) will also trigger the fallback path, silently buffering the entire response body into memory and retrying digest generation, potentially masking a real bug in the custom generator and changing error-propagation behavior for streamed/large responses.

→ Check: Isolate the try/catch to only `res.clone()` (not the digest generation call) so generator errors still propagate normally, and add a test where a custom generateDigest throws to confirm the error surfaces rather than being masked by the fallback.

### 🟢 Low — src/middleware/etag/index.ts:99 — performance

On fallback, the entire response body is loaded into memory via `res.arrayBuffer()` instead of being streamed, which could be a performance/memory concern for large responses in environments hitting this path repeatedly.

→ Check: Confirm this fallback is only expected to trigger rarely (Lambda-like envs) and document/verify memory implications for large bodies.
