### 🟡 Medium — src/middleware/etag/index.ts — breaking-change

The `await c.res.blob() // Force using body` call was removed from the code path that runs when the ETag matches (304 case). This line existed presumably to fully consume/drain the underlying response stream so it doesn't leak or block. Removing it could reintroduce stream-consumption issues (e.g., unhandled/leaked ReadableStream, or in some runtimes an unconsumed body causing warnings or resource leaks) for the 304 response path, especially since `res.clone().body` is read elsewhere but the original response body may still be unconsumed in this branch.

→ Check: Verify in each target runtime (Node, Deno, Bun, Cloudflare Workers) that omitting `c.res.blob()` before replacing `c.res` with a new 304 Response does not leave the original response's body stream unconsumed/locked, causing warnings, leaks, or hangs. Add/keep a regression test that checks no dangling stream warnings occur on repeated ETag-matched requests.

→ Check: grep the codebase for other usages of `generateDigest` from './digest' to confirm index.ts is the only caller, and that no external tests or examples call it with the old single-argument signature.
