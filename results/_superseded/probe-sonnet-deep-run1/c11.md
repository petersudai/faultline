## Summary
This PR extends greedy param matching (`:name{.+}`) to also work correctly when followed by static path segments, by embedding a lookahead into the generated regex (`getPattern`) and by adding a deferred-node queue (`curNodesQueue`) in the trie-router search algorithm to re-visit nodes after a greedy match consumes multiple path segments. Both linear-router and trie-router got matching implementations plus new tests in the shared `common.case.test.ts`. The trie-router's new queue/index logic for re-inserting nodes after a greedy match is non-trivial and its coverage for deeper nesting (more than two additional static segments after a greedy capture) is unclear.
