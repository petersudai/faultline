## Summary
This PR changes `route()` to wrap a sub-app's routes in `compose([r.handler], app.errorHandler)` when the sub-app has a custom errorHandler, so errors thrown in a sub-app's handler are caught by the sub-app's own errorHandler instead of bubbling to the parent's. It also swaps the `compose()` argument order (onNotFound/onError -> onError/onNotFound), with all callers in this repo (hono.ts dispatch, compose.test.ts) updated consistently. The main residual risk is that detecting a "customized" errorHandler relies on reference equality (`app.errorHandler === errorHandler`) against the module-scoped default handler, which is a fragile mechanism that could silently misbehave if the default reference ever diverges (e.g. duplicate module instances from bundling).
