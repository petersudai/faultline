## Summary
This PR adds a `basePath` constructor option to `Hono` while deprecating `app.basePath()`, refactoring the internal base path storage from a TS-private field to a native `#basePath` private field, and updating `route()` to clone+merge directly instead of calling the deprecated `basePath()` method. Tests are updated extensively to cover the new option and existing behavior; the main risks are subtle type-level changes to the `route(path)` single-argument overload and potential instance-property shadowing from `Object.assign(this, options)` including `basePath` as a plain property.

## Findings (3)

### 🟡 Medium — src/hono-base.ts:156 — breaking-change

The single-argument overload of `route(path)` (used to set a base path without a sub-app, e.g. `app.route('/api')`) has been removed from the type signature. Previously there was an explicit overload `route<SubPath extends string>(path: SubPath): Hono<E, RemoveBlankRecord<S>, BasePath>` marked as deprecated/removed-in-v4, but it still existed as a valid call at the type level. Now only the two-argument-or-optional-app overload remains; TypeScript users calling `app.route('/x')` without an app argument will still compile since `app` is optional, but the return type inference (RemoveBlankRecord<S> vs MergeSchemaPath<undefined,...>) changes, potentially altering downstream type inference for schema-dependent consumers (e.g. RPC client type generation).

→ Check: Verify that `app.route(path)` without a second argument still produces the same schema type as before (RemoveBlankRecord<S>) for RPC/client type inference use cases, and add a type-level test.

### 🟢 Low — src/hono-base.ts:133 — unhandled-edge-case

`Object.assign(this, options)` is called even after `basePath` has been deleted... actually basePath is NOT deleted from options like strict is, so `Object.assign(this, options)` will also assign a public `basePath` property (string) onto the instance in addition to the private `#basePath` field, potentially shadowing/conflicting with the `basePath()` method defined on the prototype. Need to confirm this does not silently override the `basePath` method with the string value passed in options, breaking `app.basePath('/x')` calls at runtime.

→ Check: Test that after `new Hono({ basePath: '/api' })`, calling `app.basePath('/more')` still works and returns a function-typed subApp, not throwing 'app.basePath is not a function' due to instance property shadowing the prototype method.

### 🟢 Low — src/hono-base.ts — api-contract

Switching `_basePath` (a regular private field) to `#basePath` (native private field) changes it from TS `private` (which is still accessible via bracket notation/any-cast in JS at runtime) to true runtime-private. This is likely fine but could break any subclasses or tests directly manipulating `_basePath` via casting, or usages of `route()`/`basePath()` in subclasses that inherited access to `_basePath`.

→ Check: Search codebase and any downstream middleware packages for direct references to `_basePath` that would now break due to the private field rename to `#basePath`.
