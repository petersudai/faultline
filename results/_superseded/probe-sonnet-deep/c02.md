## Summary
This PR adds a fallback for environments (e.g., AWS Lambda) where `res.clone()` throws, reading the whole body via `arrayBuffer()` instead and reconstructing the response. The change is scoped to the etag middleware and includes a new test for the Lambda-like scenario, but the broad try/catch also swallows errors thrown by the digest generator itself (not just clone() failures), silently changing behaviour for that unrelated case with no test coverage.

## Findings (3)

### 🟡 Medium — src/middleware/etag/index.ts:97 — error-handling

The try/catch wraps `generateDigest(res.clone().body, generator)` as a whole, intending to catch only `res.clone()` failures (e.g. AWS Lambda). But it also catches errors thrown from inside `generateDigest`/the user-supplied generator itself. Previously such errors propagated; now they trigger the fallback path (re-reading the body via `res.arrayBuffer()` and re-invoking the generator), silently changing behavior for an unrelated failure mode.

→ Check: Scope the try/catch to only the `res.clone()` call (not the whole generateDigest invocation), or add a test where a custom generateDigest throws to confirm the error still propagates instead of being swallowed.
