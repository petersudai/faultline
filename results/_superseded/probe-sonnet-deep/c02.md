## Summary
This PR adds a fallback in the etag middleware: if `res.clone()` throws (e.g. AWS Lambda-like environments), it buffers the whole body via `res.arrayBuffer()` and rebuilds `c.res` from that buffer. `generateDigest` was extended to accept an ArrayBuffer as well as a stream. The main risk is that the try/catch wraps the entire `generateDigest(res.clone().body, generator)` call rather than just the `res.clone()` call, so an error thrown later (e.g. by a user-supplied `generateDigest`, or while reading the cloned stream) is also swallowed and triggers a second, redundant read+digest of the body, potentially double-invoking a user's digest generator and masking the real error. Tests only cover the simple case of `clone()` synchronously throwing, not generator failures or preservation of headers/status through `new Response(buffer, res)`.

## Findings (2)

### 🟡 Medium — src/middleware/etag/index.ts:97 — error-handling

The try block covers both res.clone() and the subsequent generateDigest call. If clone() succeeds but reading/generating the digest from the cloned stream throws partway through (e.g. custom generateDigest throws, or stream errors after some bytes were consumed), the catch treats it the same as an unsupported clone() and retries with res.arrayBuffer() on the original response — potentially double-invoking a user's digest generator and masking the real error, or throwing an unhandled error if the original response body was already partially read.

→ Check: Verify only the clone() call itself is guarded (e.g. by calling res.clone() outside/before the digest generation, or checking for clone support up front), and confirm behavior when a custom generateDigest throws — it should not be silently retried.

### 🟢 Low — src/middleware/etag/index.test.ts — test-gap

The added test only covers the case where res.clone is overridden to throw synchronously; it doesn't test the case of the fallback path itself failing, or a custom generateDigest throwing, or verifying that response headers/status are preserved via new Response(buffer, res) versus the original res.

→ Check: Add a test asserting all original response headers/status/statusText survive the fallback path, and a test exercising a failure deeper in generateDigest to confirm it isn't misclassified as a clone-unsupported case.
