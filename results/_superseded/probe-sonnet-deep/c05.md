## Summary
This PR adds a `basePath` constructor option and deprecates `app.basePath()`, converting internal base-path storage from a plain `_basePath` property to a private class field `#basePath`. The core routing logic (`route`, `mount`, `addRoute`) reads `this.#basePath` directly and appears well covered by updated tests. However, the constructor still does `Object.assign(this, options)` (which copies a `basePath` string property onto the instance) before separately assigning `this.#basePath = options.basePath ?? '/'` — this causes the assigned `basePath` string to shadow the prototype's `basePath()` method on instances created with `{ basePath: '/x' }`, so a subsequent `app.basePath(...)` call on such an instance would throw instead of behaving as a method. This combination is not covered by the updated tests.

## Findings (1)

### 🟡 Medium — src/hono-base.ts:133 — unhandled-edge-case

`Object.assign(this, options)` copies all option keys (including `basePath`) onto the instance as own properties. Since `basePath` is also the name of an existing prototype method, an instance created via `new Hono({ basePath: '/api' })` will have `this.basePath` overwritten with the string '/api', shadowing the `basePath()` method on the prototype. Calling `.basePath('/more')` afterward would throw since it's now a string, not a function.

→ Check: Test `new Hono({ basePath: '/api' }).basePath('/more')` and confirm it either works as intended or throws a clear TypeError; if the latter, consider excluding `basePath` from the Object.assign or documenting this as unsupported.
