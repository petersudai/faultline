## Summary
This PR fixes a bug where compress middleware buffered server-sent events (SSE) instead of streaming them, by excluding text/event-stream from the compressible content-type regex. The change is small, targeted, and includes a test verifying SSE responses aren't compressed; risk is low since it only narrows what gets compressed and doesn't change any public API surface.

## Findings (2)

### 🟢 Low — src/utils/compress.ts — unhandled-edge-case

The regex now excludes text/event-stream from compressible content types using a negative lookahead. This is a narrow, well-scoped change but relies on regex correctness for edge cases like 'text/event-stream;charset=utf-8' or content types with extra whitespace; a subtle regex bug could either still compress SSE (regression not fixed) or incorrectly exclude other text/* types if the lookahead is malformed.

→ Check: Manually verify the regex against variations like 'text/event-streamx' (should still match, i.e. still compressible), 'text/event-stream; charset=utf-8' (should not match), and 'text/event-stream' alone, to ensure lookahead boundaries are correct.

### 🟢 Low — src/middleware/compress/index.test.ts — test-gap

The new test checks byte length equality (13000) as an implicit proxy for 'not compressed', which is somewhat fragile and implementation-detail-dependent (depends on exact SSE payload size), but is a reasonable smoke test for the fix.

→ Check: Confirm the test asserts more directly that no Content-Encoding header is set on the SSE response, in addition to the byte-length check, to make the test more robust against unrelated payload size changes.
