## Summary
This PR adds a `basePath` constructor option to Hono, refactors the private `_basePath` field to a true private `#basePath`, deprecates `app.basePath()`, and updates tests/Deno-dist mirrors accordingly. The main risk is the potential name collision from `Object.assign(this, options)` writing `options.basePath` onto the instance, which could shadow the `basePath()` prototype method, plus the quiet removal of the single-argument `route(path)` type overload that some consumers may rely on for typing.

## Findings (3)

### 🟡 Medium — src/hono-base.ts:156 — breaking-change

The single-argument overload of `route(path)` (used to set a base path without a sub-app) has been removed from the type signatures, along with the previously exported `RemoveBlankRecord` import used for that overload's return type. Any consumer relying on `app.route('/api')` (one-argument form) for TypeScript typing will now hit a type error, or if such usage still exists at runtime it's not obviously exercised in tests. This narrows the public API surface without an accompanying deprecation notice comment (the removed comment even says 'route with one argument has been removed in v4' implying it should still exist until v4).

→ Check: Confirm whether `app.route(path)` single-argument usage is still supported/tested elsewhere, and whether removing this overload is intentional for this PR versus accidental scope creep unrelated to the basePath option feature.

### 🟢 Low — src/hono-base.ts:128 — unhandled-edge-case

`Object.assign(this, options)` still assigns `basePath` from options onto `this` as a property (since HonoOptions includes `basePath`), potentially creating a public `this.basePath` string field colliding with the `basePath()` method on the prototype instance, since instance own-properties would shadow prototype methods. This could silently break the deprecated `app.basePath()` method when the `basePath` option is used in the constructor, since assigning `options.basePath` (a string) as `this.basePath` would shadow the class method.

→ Check: Verify that constructing `new Hono({ basePath: '/api' })` and later calling `app.basePath('/foo')` still works, or add a test confirming `Object.assign` does not clobber the `basePath` method with the string value from options.

### 🟢 Low — src/hono-base.ts:131 — other

Constructor mutates the input `options` object via `delete options.strict`, mutating caller-supplied objects, which is a minor code smell/side effect but preexisting behavior extended, not newly introduced.

→ Check: Confirm callers don't reuse the same options object across multiple Hono instantiations expecting it to remain unmodified.
