## Summary
This PR adds a fast path to `c.json()` mirroring the existing `c.text()` optimization to skip `#newResponse()`'s Headers allocation for simple JSON responses. ### 🔴 High — src/context.ts — api-contract

The description states the implementation creates `new Response(jsonString, { headers: { 'Content-Type': 'application/json' } })`, but the actual diff uses `Response.json(object)`. `Response.json()` sets the Content-Type as `application/json` via the Headers API (returning a real Headers instance, not a plain object), which defeats the stated performance goal (avoiding Headers allocation and enabling the node-server fast path that checks `header instanceof Headers`). This is a functional mismatch between the PR's stated intent/benchmarked approach and the shipped code — the perf benefit described likely will not materialize, and downstream optimizations (node-server PR #301) may not engage as expected.

→ Check: Verify whether `Response.json()` in the target JS runtime returns headers as a plain object or a Headers instance internally, and confirm the node-server adapter's `instanceof Headers` fast-path still triggers with `Response.json()`-created responses. If not, replace with a manually constructed Response using a plain headers object as described in the PR text.

### 🟡 Medium — src/context.ts — unhandled-edge-case

`Response.json(object)` will throw on values that are not JSON-serializable in the same way as `JSON.stringify` in some edge cases (e.g., differs in handling of `undefined`, functions, circular references may throw either way but error messages/behavior could differ), and importantly `Response.json()` internally calls `JSON.stringify` per spec, but behavior on non-serializable top-level values (like `undefined`) diverges from explicit `JSON.stringify(undefined)` producing `undefined` (invalid body) vs `Response.json(undefined)` behavior. This edge-case divergence between the fast path and slow path (`#newResponse` with `JSON.stringify`) could cause inconsistent results depending on whether `arg`/`headers` were passed.

→ Check: Add/verify test cases for `c.json(undefined)`, `c.json(null)`, and other edge-case payloads to confirm identical behavior between the fast path and the slow path.

### 🟢 Low — src/context.ts — test-gap

No test file changes are included in the diff; a new fast path for c.json() with distinct behavior (via Response.json) should have dedicated tests confirming header casing, content-type value, and status code parity with the previous behavior.
