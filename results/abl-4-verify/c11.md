## Summary
This PR adds support for greedy route parameters with subsequent static components (e.g., `/:dirs{.+}/file.html`). The implementation uses lookahead assertions in regex patterns and a queue-based search mechanism. The changes are well-tested, but there is a potential cache key collision issue in getPattern() when the `next` parameter varies.

## Findings (1)

### 🟡 Medium — src/utils/url.ts:62 — unhandled-edge-case

The cache key uses `${label}#${next}` which becomes `label#undefined` when next is undefined. This could cause cache collisions if the same pattern is used in different contexts (with and without a next component). The cache should distinguish between these cases more robustly.
