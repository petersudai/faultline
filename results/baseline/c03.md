## Summary
This PR modifies `createMiddleware` to relax TypeScript type constraints for `Bindings` and `Variables` by automatically adding `any` to undefined properties. The change allows middleware with partial type specifications to compose without type errors. The main risk is that this type relaxation could mask legitimate type mismatches and reduce type safety in middleware composition.

## Findings (4)

### 🟡 Medium — src/helper/factory/index.ts:244 — api-contract

The `AddAnyToEnv` type transformation silently converts undefined `Bindings` or `Variables` to `any`, which weakens type safety. A middleware author specifying only `{ Variables: Variables }` will now accept any `Bindings` type without explicit opt-in. This could allow accidental misuse where incompatible bindings are passed through.

→ Check: Verify that this type relaxation is intentional and document it clearly. Consider whether users expect `any` to be injected for unspecified properties, or if they should explicitly opt into this behavior.

→ Check: Confirm that using `E2` throughout (instead of `E` in the return type) is the intended behavior and that this doesn't break existing code that relies on the stricter `E` type.
