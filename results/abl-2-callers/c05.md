## Summary
This PR adds a `basePath` constructor option to Hono and deprecates the `app.basePath()` method. The main risk is that the `clone()` method does not preserve the current instance's `#basePath` when creating a cloned instance, which could cause incorrect path merging in nested route scenarios.

## Findings (3)

### 🔴 High — src/hono-base.ts:138 — unhandled-edge-case

The `clone()` method does not preserve the current instance's `#basePath` when creating a cloned instance. When `clone()` is called, it creates a new Hono with only `router` and `getPath` passed, causing the cloned instance to have `#basePath = '/'` by default. While the calling code in `route()` and `basePath()` immediately overwrites this with the merged path, this creates a window where the clone has an incorrect basePath. More critically, if the clone's basePath is not immediately overwritten (e.g., in future code paths or edge cases), routes added to the clone before the basePath is set will use the wrong prefix.

→ Check: Verify that `clone()` should pass the current instance's `#basePath` to the constructor: `const clone = new Hono<E, S, BasePath>({ router: this.router, getPath: this.getPath, basePath: this.#basePath })`. Test nested route scenarios with multiple levels of `route()` calls to ensure paths are correctly merged.

### 🟡 Medium — src/hono-base.ts:159 — api-contract

The `route()` method implementation changed from calling `this.basePath(path)` (which is now deprecated) to directly cloning and setting basePath inline. While functionally equivalent, this bypasses the deprecated method and may mask issues if the deprecated method had side effects or validation logic that should still apply.

→ Check: Confirm that the inline implementation of `route()` (lines 159-160) is functionally identical to the old implementation that called `this.basePath(path)`. Verify no validation or side effects were lost in the refactoring.

### 🟡 Medium — src/hono-base.ts:79 — unhandled-edge-case

The `#basePath` field is declared without initialization (`#basePath: string`). While it is always set in the constructor before use, TypeScript's strict mode may flag this as potentially uninitialized. More importantly, if the constructor logic changes or if `#basePath` is accessed before the constructor completes, this could cause runtime errors.

→ Check: Initialize `#basePath` with a default value: `#basePath: string = '/'` to match the old `private _basePath: string = '/'` behavior and ensure the field is always in a valid state.
