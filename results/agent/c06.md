## Summary
This PR changes the `compose` function signature by swapping the parameter order of `onError` and `onNotFound`, and adds logic to wrap sub-app handlers with the sub-app's error handler when routing. The changes include comprehensive tests for nested app error and notFound handling. The main risk is the breaking change to the public `compose` API signature, which could affect external callers, though internal usage is updated.

## Findings (3)

### 🔴 High — src/compose.ts:12 — breaking-change

The `compose` function signature has been changed by swapping parameter order from `(middleware, onNotFound, onError)` to `(middleware, onError, onNotFound)`. This is a breaking change to a public exported API. While internal call sites in hono.ts have been updated, any external code calling compose directly with positional arguments will break silently or behave incorrectly.

→ Check: Verify if compose is part of the public API contract. If so, consider using function overloads or a deprecation period. Check if there are any external consumers of this function in the ecosystem.

### 🟡 Medium — src/hono.ts:125 — unhandled-edge-case

The identity check `app.errorHandler === errorHandler` relies on the module-level `errorHandler` constant. This works for default handlers but could be fragile if errorHandler is reassigned or if multiple instances of the module exist (e.g., in bundled code). The check assumes reference equality which may not hold in all environments.

→ Check: Consider adding a flag or property to track whether an errorHandler is custom vs default, rather than relying on reference equality. Test with bundled/minified code to ensure the identity check still works.

### 🟡 Medium — src/hono.test.ts:1028 — test-gap

The test at line 1028-1032 expects `/sub/implicit-404` to be handled by the parent app's notFound handler ('404 Not Found by app'), but this is inconsistent with the error handler behavior where the sub-app's custom error handler IS used (line 974-977). The test comment says 'should be handled by sub' but the assertion checks for 'by app'. This suggests either the test is wrong or the notFound behavior is intentionally different from error behavior, which should be documented.

→ Check: Clarify the intended behavior: should sub-app notFound handlers be used like error handlers, or should they always fall back to the parent? Update the test comment and assertion to match the intended behavior, or fix the implementation to be consistent.
