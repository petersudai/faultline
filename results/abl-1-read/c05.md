## Summary
This PR adds a `basePath` option to the Hono constructor and deprecates the `app.basePath()` method. The main risk is a bug where `Object.assign(this, options)` copies the `basePath` property to the instance, creating a public property that shadows the `basePath()` method, breaking the deprecated method for apps created with the option.

## Findings (3)

### 🔴 High — src/hono-base.ts:133 — unhandled-edge-case

Line 133 calls `Object.assign(this, options)` which copies the `basePath` property from options to the instance as a public property. This creates a property that shadows the `basePath()` method defined on the class (line 182). After this assignment, `app.basePath` will be a string instead of a function, breaking any code that tries to call `app.basePath('/path')` on an app created with `new Hono({ basePath: '/api' })`. The code deletes `strict` before Object.assign but fails to delete `basePath`.

→ Check: Verify that `Object.assign(this, options)` does not create a public `basePath` property that shadows the method. Either delete `basePath` from options before the assign (like is done for `strict`), or use destructuring to exclude it. Test calling `basePath()` method on an app created with the `basePath` option to confirm it still works.

### 🟡 Medium — src/hono.test.ts — test-gap

The test suite does not cover calling the `basePath()` method on an app created with the `basePath` option. Tests at lines 114-131 use the option but don't call the method; tests at lines 133-150 use the method but don't use the option. This gap means the shadowing bug would not be caught by existing tests.

→ Check: Add a test that creates an app with `new Hono({ basePath: '/api' })` and then calls `.basePath('/sub')` to verify the method still works and returns a properly configured sub-app.

### 🟢 Low — src/hono-base.ts:79 — other

The private field `#basePath` is declared without an initializer (line 79), relying on the constructor to initialize it (line 134). While this works, it's a minor code quality issue since the field is uninitialized until the constructor runs. The field should either have a default initializer or be declared as `#basePath: string = '/'`.

→ Check: Consider adding a default initializer to the `#basePath` field declaration for clarity and to prevent potential issues if the field is accessed before initialization.
